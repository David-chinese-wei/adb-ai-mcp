## 1. 首次连接

### 方式 A：USB（最省事）

1. 手机：设置 → 关于手机 → 连点「版本号」7 次 → 开发者选项出现
2. 开发者选项里打开 **USB 调试**
3. 数据线连电脑，手机上弹窗点「允许」（可勾「始终允许」）
4. 让 AI 跑一下：

```
跑一下 env_check
```

看到设备状态是 `✓ 在线` 就成了。

### 方式 B：WiFi（连一次之后可以拔线）

1. 先用 USB 连着，让 AI 执行：
   ```
   用 connect_wifi 连我的手机，IP 是 192.168.1.20
   ```
   （IP 在手机 WiFi 详情里看，或让 AI 跑 `device_info` 直接读出来）
2. 看到 `connected to 192.168.1.20:5555` 后拔掉线，依然能操作

> Android 11+ 也可以完全不插线：手机开发者选项 → 无线调试 → 「使用配对码配对」，
> 把显示的 IP、端口、配对码告诉 AI，让它调 `adb_pair`。

### 连不上时

按顺序试：

```
跑 env_check        → 看 adb 找没找到、设备什么状态
重启一下 adb        → restart_adb
```

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `unauthorized` | 手机上没点允许 | 点「允许 USB 调试」 |
| `offline` | adb 连上了但握手失败 | 换线 / 重插 / 重开 USB 调试 / `restart_adb` |
| 列表为空 | adb 没看到设备 | 确认开发者选项和 USB 调试都开了 |

## 2. 让 AI 看清屏幕

两种方式，各有分工：

| 工具 | 返回什么 | 适合 |
| --- | --- | --- |
| `screenshot` | 一张真实截图（图片） | 看整体画面、看图看视频、判断界面长什么样 |
| `ui_dump` | 所有控件的文字、resource-id、坐标 | 精确点击、判断哪里能点 |

直接说人话就行：

```
看看我手机现在是什么界面
```

AI 会调 `screenshot`（返回压缩到 720px 宽的图，省 token），原图同时存在 `outputs/screenshots/` 下。

## 3. 让 AI 操作手机（核心循环）

AI 操作手机的正确姿势是 **`ui_dump` → 判断 → `tap`** 三步循环，而不是盲点坐标：

```
1. ui_dump        拿到所有控件和它们的中心坐标
2. 模型读文本     找到目标元素，比如 text="设置" center=(200,430)
3. tap(200, 430)  点它
4. 回到第 1 步    确认界面变了没
```

示例对话：

> **你**：帮我打开手机的设置，把亮度调到一半
>
> **AI**：
> 1. `ui_dump` 找到「设置」图标 → `tap`
> 2. `ui_dump` 找到「显示和亮度」 → `tap`
> 3. `ui_dump` 读亮度滑块位置 → `swipe` 拖动
> 4. `screenshot` 确认结果

配套动作：

| 想干的事 | 用哪个 |
| --- | --- |
| 点击 | `tap(x, y)` |
| 滑动 / 翻页 / 下拉通知栏 | `swipe(x1,y1,x2,y2,duration_ms)` |
| 返回 / Home / 最近任务 | `keyevent`（4=返回，3=Home，187=最近任务） |
| 输入英文数字 | `type_text` |
| 打开某个 App | `start_app(包名)` |
| 打开网页 | `open_url` |
| 录一段操作过程 | `record_screen(秒数)` |

## 4. 投屏演示

```
把手机投到电脑上，窗口置顶
```

AI 调 `scrcpy_start`，一个窗口就弹出来了。常用参数：

| 参数 | 作用 |
| --- | --- |
| `max_size` | 画面长边上限，越大越清晰越吃带宽（默认 1280） |
| `bit_rate` | 码率，`8M` 清晰、`2M` 流畅 |
| `no_control` | 只读，防止误操作手机 |
| `turn_screen_off` | 只投屏、熄灭手机屏（省电） |
| `always_on_top` | 窗口置顶 |
| `record_file` | 投屏的同时录成 mp4 |
| `show_touches` | 显示触摸点，教学 / 演示用 |

关掉：

```
把投屏关了        → scrcpy_stop
投屏还在跑吗      → scrcpy_status
```

## 5. 抓日志排查崩溃

```
这个 App 一打开就闪退，帮我看看日志
```

AI 会跑 `logcat` 并做关键字过滤。常用姿势：

- 先 `logcat(clear=true)` 清空，再复现问题，再 `logcat(lines=500)` —— 拿到的全是新日志
- 只想看崩溃：`filter="AndroidRuntime|FATAL|crash"`
- 只看某个包：`filter="com.example.app"`

## 6. 装 APK、传文件

```
把这个 APK 装到我手机上：D:/downloads/app.apk
把手机相册最近拍的照片拉到电脑 D:/photos
```

- `install_apk` 装包（默认 `-r` 覆盖安装保留数据）
- `uninstall_app` 卸载（会先要一次确认）
- `push_file` / `pull_file` 互传
- `list_packages` 查包名，配合 `start_app` / `stop_app` 用

## 7. 多设备怎么处理

同一个手机同时插着 USB 又连着 WiFi 时，adb 会把它当成**两台设备**。
本服务会用 `ro.serialno` 识别出「其实是同一台」，自动走 USB 通道，你不用管。

真的有多台不同设备时：

```
把默认设备设成 192.168.1.20:5555     → set_default_device
```

设一次，之后所有工具都不用再带 serial。也可以每次单独指定 `serial` 参数。

## 8. 已知限制

| 限制 | 原因 | 绕法 |
| --- | --- | --- |
| `type_text` 不能输中文 | adb 的 `input text` 只支持 ASCII | 用 `scrcpy_start` 开投屏，用电脑键盘直接打字 |
| 锁屏状态下 `ui_dump` 会失败 | uiautomator 需要界面在前台 | 先点亮解锁，或用 `keyevent 26` 唤醒 |
| 录屏最长 180 秒 | Android `screenrecord` 硬性上限 | 分段录 |
| 部分厂商 ROM 禁了 `uiautomator` | 系统限制 | 退化用 `screenshot` + 坐标估算 |
| 投屏需要 scrcpy ≥ 2.0 | 旧版参数不兼容 | 升级 scrcpy |

## 安全边界

AI 能执行的命令分三级：

- **只读命令**（`ls`、`cat`、`getprop`、`dumpsys`…）→ 直接跑
- **有副作用的命令**（`rm`、重启、卸载应用、改系统设置、`su`）→ 第一次调用返回提示，AI 会带着 `confirm: true` 再来一次才真正执行
- **不可逆破坏**（删系统分区、`dd` 写块设备、fastboot 擦除/解锁、recovery wipe）→ 直接拒绝，没商量

所以「帮我清理一下手机」这种模糊指令不会变成灾难，但**卸载 App、改设置这类操作请听清 AI 的确认提示再放行**。
